# Dynamic regression and quality gates

Phase 3 extends the Evaluation Control Centre with regression suites and a
restricted workbench. Cases and suites reuse immutable evaluation dataset
versions. A case pins the failed run, its measured case result and the
expectation already registered for that evidence. The supported source paths
are original synthetic fixtures and authorized replay of exact governed
references. Both retain their original evidence maturity and split.

1. Run a published evaluation and inspect a measured failure in its run detail.
2. Promote the exact failed case result in the regression workbench and submit
   its version for review. A genuine approved reference observation is also
   eligible through the restricted API when the exact run, result, adjudication
   and processing rights verify. An independent reviewer can approve or reject
   the version. Publication requires approval.
3. Assemble and publish a suite with one or more exact case version pins.
   A suite successor requires the exact preceding version. The workbench can
   inspect earlier versions and their recorded comparisons.
4. Compare exact existing execution runs as an independent evaluator.
   Each side can pin a group of compatible primary runs for a multi-case suite.
   Every run must verify its own dataset, observation or execution receipt.
   Compatible synthetic versions can differ in their observations while keeping
   the same input, reference, split, scoring semantics and metric settings.
   A repeat study uses distinct existing execution receipts with identical
   configuration. Its findings describe repeatability and reference error.
5. Record a separate human recommendation on the exact comparison checksum.
   Accepting technical evidence leaves the release recommendation
   `NOT_READY` while the empirical gate is unconfigured.

Measured checks show numerator, denominator and per-case outcome. Missing
required measurement yields `NOT_EVALUATED`. Incompatible scopes, reference
cohorts, scoring scales or execution identities yield `NOT_COMPARABLE`.
Held-out cases remain in their registered split. Broad platform views return
safe metadata and measurement counts, while processing private source evidence
requires current access in the owning institution.

The threshold registry starts empty. A policy definition pins the metric
implementation and settings, an exact evaluation suite, a separate genuine
calibration study, paired coverage requirements, the proposed boundary, dates
and study rationale. Approval requires an independent qualified human and
current access to the approved references. The application reports
`UNCONFIGURED` without an exact approved policy pin. The synthetic browser
journey proves technical comparison only.

Historical replay supports the exact version identities available in stored
Writing, Speaking and transcription receipts. Real retrieval configuration
comparisons require a durable execution receipt that is currently unavailable.
The existing genuine reference replay path is limited to its registered
population and receipt shapes. Multi-case technical fixtures do not supply a
genuine calibration study. Published rubric changes must preserve the
comparison's scoring and evidence semantics.

Recommendations link to the immutable comparison and candidate artifact pins.
Model, prompt, rubric, workflow and Standard Pack publication authority comes
from the existing human approval workflows. Those publication APIs currently
have no quality-gate reference input.
