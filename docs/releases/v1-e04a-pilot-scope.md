# V1-E04A Berlin practice scope and result confidentiality

`V1_PILOT_PROFILE` is server configuration. It defaults to `DISABLED`, which keeps the regular application profile. `BERLIN_LID_LOCKED` restricts the API and workspaces to the proposed pilot scope and refuses assignment and delivery until there is an E03A approved-manifest decision. `BERLIN_LID_SYNTHETIC` is for the Alembic-migrated disposable acceptance database only. Production and unrecognized database targets reject it. It revalidates the existing Berlin-only practice form, assessment classification, tenant, and attempt pins. An existing editorial publication receipt or synthetic form cannot satisfy the future E03A approval check.

The restricted profile permits authentication and enrollment, candidate practice and release reads, institution assignment, objective scoring, human review, explicit release and revocation, plus limited Control Centre oversight. An allowlist applies to the resolved FastAPI route and HTTP method. Normal authentication and resource authorization still apply. Platform oversight does not replace tenant authority for pilot scoring and release. New endpoints require an explicit scope decision. Audio and AI worker claims are also unavailable in this profile. Outside the restricted profile, the existing application journeys continue to use their normal permissions.

Candidate result and statement endpoints keep their tenant and ownership checks and refuse withdrawn outcomes. Legacy score endpoints require the active release for LiD. Candidate API responses default to `no-store`. The browser checks the current release of the exact result version before displaying a score or statement and while the page is visible. An offline or backgrounded page clears that authorization. An already visible, connected page polls every two seconds, with a short allowance for the response. Server reads are denied after revocation commits. The browser cannot retract information somebody has already seen or reproduce the immediacy of a server decision on an open page between checks.

The disposable browser suite retains the existing journeys and restarts only its own local API to exercise the synthetic profile. It holds a real, previously authorized score response until after revocation and then verifies that the browser suppresses it. It also exercises the normal release and revoke states, role boundaries, wrong-tenant access, offline hiding, legacy endpoints and prior interruption protections. The required LiD PostgreSQL and guarded MinIO report covers the profile lock before E03A and stale form pins. Diagnostic files for this browser spec remain outside public artifact uploads.

PR #59’s historical review exception, PR #60’s P2 disposition, and PR #61’s pre-merge review exception remain open. E03A, H01, H04/H05, H06, H10, storage and incident readiness, and official certification have their own authorization and evidence. E04A technical evidence does not confer product signoff or authorize pilot launch.
