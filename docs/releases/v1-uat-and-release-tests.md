# V1 UAT and release tests

The goal is an accessible, correctly bounded Berlin LiD practice journey from institutional enrollment through an explicitly released result. Start with disposable synthetic dry runs. Start real participant sessions only after product scope, participant/privacy processing and the UAT environment have been authorized (H01, H06 and the approved UAT protocol in H10). The prospective release form must match the rights and examiner decisions before it is shown to participants. Use separate candidate, examiner, release operator, Control Centre and unauthorized identities. Record the role and a study ID, and keep participant identity in the approved study channel.

Use the selected build, deployment configuration, single Alembic head and pinned item manifest. Record browser/OS, viewport, input method, assistive technology version where applicable, task, expected and actual behavior, evidence reference, severity, retest and observer. Use approved access and retention for any captures. Avoid candidate answers, credentials, object keys and unnecessary personal details in shared issue reports. Record pass, fail, blocked or not run for each scenario. Real human UAT is **NOT VERIFIED**.

Before pilot launch, reconcile results against E01–E06, H06, H10, O01–O07 and A01–A02 in the [register](v1-readiness-register.md). With disposable synthetic identities, run the exact release candidate through required CI, validate flags and denied routes for excluded features, verify release/revoke and tenant isolation through direct requests, and rehearse recovery and stop procedures. A regression affecting confidentiality, rights, access, scoring integrity or the ability to complete core tasks requires disposition and a retest on the corrected revision. Carry human findings and environment evidence into the separate H12 launch decision.

The [V1-E05A synthetic dry run and human UAT worksheet](v1-e05a-synthetic-uat.md) covers U03–U05 and U10–U13. Record any human observations on the actual retest commit.
