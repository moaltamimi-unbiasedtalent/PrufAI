# P1A personal-data and assessment evidence inventory

Source baseline `c3548ef8293b2cb7cfb05a9fd3b7719829a6cd62`, Alembic `0042_initial_review_authority`. This is a repository inventory. Hosting configuration, actual backups, contracts and production data are outside the inspected evidence. No real subject or object values are used.

**Default for every category.** Candidate retention policy is `UNCONFIGURED` and deletion eligibility is `NOT_DETERMINED`. The TTLs, grants, access states and rights windows below govern technical behavior. They do not establish an approved records schedule. The responsible team in the inventory denotes technical ownership. The legal controller and processor roles for each purpose are unverified.

**Storage convention.** Named model tables are authoritative PostgreSQL records unless stated otherwise. Service-level permission, tenant and ownership checks protect normal access. Some tables hold both content and identifiers and require access at the record and field level. Database transport security, encryption at rest, key custody, replica coverage, hosting provider and backup retention are `NOT VERIFIED` for every row. The local compose files show service volumes only. See [storage and processors](storage-processors.md) for secondary copies, transport and recovery.

## Exact lineage and evidence rules

1. Start with an authenticated request scope. Match organisation and candidate at assignment and attempt. Follow each item binding and response revision using exact IDs. Parent-child checks must agree with redundant tenant and subject fields. A global user ID alone is insufficient.
2. For Writing, follow the response revision into the exact job, validated proposal or human assessment, criterion evidence, review checksum, scoring snapshot and result version. Distinguish current draft, immutable review and authoritative released result. For objective answers, check version-pinned answer evidence and snapshots before considering any future change.
3. For Speaking, follow recording session → media asset → media binding → exact response revision. Check object size, SHA-256 and content identity. Join transcription and proposal jobs through their pinned asset/binding/revision, and review provenance through exact assessment version. Deduplicate physical object references without discarding historical dependencies.
4. Follow ScoringRun → ItemScores/Components → ResultVersion → exact release → statement/certificate. Include appeal/moderation/correction and supersession paths. Scan typed audit, evaluation and feedback references under their own authorization and reject ambiguous ownership. Do not infer entitlement from a JSON UUID alone.
5. Mark references outside the reviewed relation, conflicting keys, unknown copy classes, unverifiable backups and provider receipts as unresolved. No dependency may be assumed absent because an API projection omits it.

The existing required suites cover real persisted examples for [candidate runtime](../../../services/api/tests/test_candidate_runtime_postgresql_integration.py), [human Writing](../../../services/api/tests/test_integrated_writing_postgresql_integration.py), [audio identity and streaming](../../../services/api/tests/test_recorded_audio_postgresql_minio_integration.py), [transcription](../../../services/api/tests/test_transcription_execution_postgresql_minio_integration.py), [Writing execution](../../../services/api/tests/test_writing_execution_postgresql_integration.py), [Speaking execution](../../../services/api/tests/test_speaking_execution_postgresql_minio_integration.py), [Speaking scoring](../../../services/api/tests/test_speaking_results_postgresql_minio_integration.py), [governed result release](../../../services/api/tests/test_result_release_postgresql_integration.py), [expert references](../../../services/api/tests/test_expert_references_postgresql_integration.py) and [feedback](../../../services/api/tests/test_governed_feedback_postgresql_integration.py). These are domain integration checks. A combined subject discovery or deletion preview has no deployed interface.
