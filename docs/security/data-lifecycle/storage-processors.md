# P1A storage, copies and external processing

This register distinguishes repository behavior from environment controls. Hosted buckets, production objects, backup payloads and provider accounts were not accessed. All examples are key shapes and schema references.

## Private object and temporary media classes

| Class | Owner and identity | Access, failure and recovery today |
| --- | --- | --- |
| Staged and validated original candidate audio | [Audio service](../../../services/api/app/speaking_audio/service.py) and [models](../../../services/api/app/models/speaking_audio.py). Key shape `candidate-audio/{organisation}/{attempt}/{recording}`, minted by the server. Staged receipt precedes PUT. The finalized asset uses the same key and pins owner, attempt, item, size, media type, duration and SHA-256. The immutable media binding pins the exact response revision. | S3-compatible object with private ACL. API validates candidate ownership or authorized institution access before streaming, with bounded backend ranges. Recovery checks the exact staged/final identity and content. A mismatched or missing object fails closed. A failed write can leave a receipt without bytes, and a completed PUT can precede the final database record. A staged object is therefore not an orphan merely because there is no finalized asset. |
| Rejected, canceled or superseded recordings | Same recording and asset classes. Failed validation before PUT can leave only a recording row. A failed, canceled or superseded recording may still have an exact object or historical revision dependency. | Lifecycle states and access checks restrict use. No general orphan scanner, approved cleanup path or candidate-object deletion method was found. A future scanner must separate staged, finalized, referenced historical, contradictory and unclassified states. It must account for a racing finalize or worker before reporting an object unreferenced. |
| Media-validation work files | [Audio inspection](../../../services/api/app/speaking_audio/media.py) writes a temporary input in a dedicated directory for bounded decoder execution. The durable receipt records media-validation identity and provenance rather than a decoder file. | Local-only process files with normal context-manager cleanup. Abrupt host/process termination or snapshot capture can retain copies. Inspect OS temporary locations, filesystem encryption, container mounts and crash behavior per deployment. |
| Derived Speaking transport | [Speaking transport](../../../services/api/app/speaking_execution/audio_transport.py) derives WAV bytes and records source digest and transport identity, including a separate transport checksum. The worker revalidates the primary bytes before derivation. This is not a persistent rendition or a second `candidate_media_assets` object. | Conversion uses temporary files and sends a bounded transport payload in memory. Temp files use normal cleanup. Derived output/provenance may exist in assessment execution and at a configured external processor. The original remains unchanged. |
| Transcription output | [Transcription model](../../../services/api/app/models/speaking_audio.py) persists transcript and segments in PostgreSQL with source digest, job, model/configuration and version references. [Worker](../../../services/api/app/speech_transcription/execution.py) reads the pinned private audio. | No separate stored transcription object class found. Provider-side working copies, if used, are separate from the repository. Canceling a job or superseding a transcript does not erase the source, the transcript, or provider copies. |
| Source files | [Registry](../../../services/api/app/services/knowledge.py) and [object adapter](../../../services/api/app/knowledge/storage.py). Key shape `standards/{source}/{document_version}/{sha256}` for the current file upload flow. Byte checksum and size are pinned to the version. Scope belongs to the source. A metadata-only registration has no file. | Registry enforces rights, version and scope before file operations, and ingestion verifies the stored bytes. PUT is outside the database transaction. Failed persistence can leave unlinked bytes, so future reconciliation must use exact version/key/checksum and source review state. Derived pages, chunks and embeddings are PostgreSQL records. |
| Question Bank media references and unclassified objects | [`question_bank_media_assets`](../../../services/api/app/models/question_bank.py) carries an item-version foreign key, `object_key`, checksum, type, rights and media details. A model reference alone does not prove a corresponding object or a particular deployed bucket. | Resolve item-version scope and actual upload/access configuration before inferring ownership. Unknown key shape, contradictory metadata, missing ownership or a shared reference means `UNSUPPORTED`. Quarantine for human inventory review without fetching contents or deleting bytes. |

The shared S3/MinIO adapter supports PUT, GET, bounded GET, HEAD and Range. It has no deletion API or application-managed bucket version ID, object lock, lifecycle rule, or orphan reconciler. The local initializer checks bucket privacy and refuses broad policies or group ACLs. Private ACLs and scoped APIs are access controls. They do not demonstrate storage-side encryption, TLS enforcement, IAM segregation, bucket versioning, replica controls or retention on a deployed system. Those settings must be verified on a separately approved environment. ### Restore acceptance before future erasure execution

Record store and generation IDs, environment/tenant boundary, encryption/key owner, retention/expiry, restore roles, RPO/RTO, recent recovery proof and replica/WAL/object generation coverage. Require two authorized roles for recovery or reconciliation where the approved operating policy calls for separation. Restore into isolation. Keep application access and external jobs disabled until durable erasure/restriction and hold receipts newer than the snapshot are reapplied or reconciled. Re-check disclosure gates and data references in all stores before reopening access. Record unmatched objects, stale grants and missing receipts as blockers. Historical backups can reintroduce data. Row deletion does not modify backup copies. P1A neither approves a restore nor changes retention or purges backups.

## Audit minimization

[AuditService](../../../services/api/app/audit/service.py) rejects credential-like metadata keys recursively and allows structured event metadata. The key check cannot recognize all personal data in string values. [Control Centre](../../../services/api/app/control_center/service.py) uses an allowlisted read projection for operational evidence rather than returning arbitrary stored metadata or reasons. Identity, entity, request and workflow IDs remain linkable. Release/certification revocation still retains a bounded free-text reason in the protected audit row for exact replay checks. Preserve it as historical evidence, record the minimization and retention decision for authorized review, and use categorical or evidence-reference fields in future designs rather than copying candidate content into reasons.

Existing regression seams include [restricted audit projection](../../../services/api/tests/test_control_center.py), [PostgreSQL platform metadata redaction](../../../services/api/tests/test_control_centre_postgresql_integration.py), [audio access and lifecycle audit](../../../services/api/tests/test_recorded_audio_postgresql_minio_integration.py), [Writing proposal execution](../../../services/api/tests/test_writing_execution_postgresql_integration.py) and [transcription provenance](../../../services/api/tests/test_transcription_execution_postgresql_minio_integration.py). They establish particular projections and emitters. Review actual request/response logging, exception messages and low-privilege log access separately. Do not log raw answers, audio/transcripts, answer keys, prompt bodies, private rationales, credential material, storage keys or full URLs.
