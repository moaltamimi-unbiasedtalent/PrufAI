## Decoder

The pinned Ubuntu Noble base used by the decoder contained APT `2.8.3`. The decoder build uses the official signed Noble archives over HTTPS and supplies the CA bundle from the existing digest-pinned Go builder. Acquisition retries are disabled before the first update and throughout the package install. The build installs and asserts fixed versions of both `apt` and `libapt-pkg6.0t64`, requiring at least `2.8.4ubuntu0.1`. The existing FFmpeg pin and offline, unprivileged decoder runtime are preserved. [Canonical CVE and fixed version](https://ubuntu.com/security/CVE-2026-109518) · [Canonical mitigation guidance](https://ubuntu.com/blog/apt-vulnerability-fixes-available)

The evidence job rebuilds the Linux amd64 decoder, verifies installed versions in the actual image with networking disabled, and asserts that its Trivy results do not contain this CVE. It preserves the image config ID, package inventory, CycloneDX SBOM, database timestamp and full findings. The required application tests exercise real synthetic audio, full inspection, invalid media, duration and timestamp rules, checksum evidence and transcription transport. The APT finding in other images remains separate.

## Storage strategies and scope

The community MinIO executable remains `RELEASE.2025-10-15T17-29-55Z` at source commit `9e49d5e7a648f00e26f2246f4dc28e6b07f8c84a`. Both advisories apply to this release. The affected discriminator is the `X-Amz-Content-Sha256` header with value `STREAMING-UNSIGNED-PAYLOAD-TRAILER` on PUT. An actor with a usable access key and a target bucket can target the vulnerable Snowball and query-credential request paths without the corresponding signature. The upstream AIStor fix is `RELEASE.2026-04-11T03-20-12Z` or later. [Pinned source authentication classifier](https://github.com/minio/minio/blob/9e49d5e7a648f00e26f2246f4dc28e6b07f8c84a/cmd/auth-handler.go) · [Snowball advisory](https://github.com/minio/minio/security/advisories/GHSA-9c4q-hq6p-c237) · [Query-credential advisory](https://github.com/minio/minio/security/advisories/GHSA-hv4r-mvr4-25vw)

A supported S3-compatible replacement requires selection, approval and compatibility evidence, including private access, multipart, Range, integrity and existing metadata. No replacement was selected. AIStor requires an active license and no PrüfAI entitlement was verified. No community fork or commercial service was introduced. This change applies the vendor's ingress workaround to the repository-defined development, demo and CI topology. [AIStor license requirements](https://docs.min.io/aistor/operations/licenses/)

| Path | Checked-in boundary |
| --- | --- |
| Python and browser CI | Fresh guarded container, synthetic CI credentials and private bucket. Only guarded S3 port 9000 is published on host loopback. The CI logs record both binary hashes. |
| Development Compose | Guarded S3 and Console at host loopback ports 9000 and 9001. Bridge peers reach the same guarded listeners. Credentials stay server-side. |
| Berlin demo Compose | Guarded S3 published at host loopback port 59000. The bridge still uses the guarded listeners. Existing UAT attempts and volumes were outside the proof. |
| Local audio helper | Guarded S3 and Console publish on loopback ports 19000 and 19001. Startup rejects a pre-existing unguarded container and leaves recreation for a separately authorized operation. |
| In-container S3 and Console | MinIO binds to private loopback ports 19000 and 19001 inside the service container. The runtime can also open the IPv6 loopback address. The embedded Console uses the guarded S3 endpoint. The front door filters both listeners before forwarding. No peer has access to the container's loopback namespace. |
| Source and audio clients | The API signs private S3 operations. Source ingestion and candidate original upload, playback and transcription transport use the existing storage abstraction and application authorization. The repository does not hand candidates general S3 write credentials. Test credentials administer disposable buckets. Production IAM and credential scopes are unverified. |

The guard rejects the marker in all parsed header values, including duplicates, and retains the signed request Host, path and query. A disposable bridge peer must receive the guard's explicit denial on both public listeners and a connection refusal on both private backend ports. The test checks the backend sockets' loopback bind, rejects synthetic requests for both advisory routes, verifies unchanged original bytes and object inventory, denies anonymous read and write, and exercises signed Put/Get/Head, bounded Range, presigned read, multipart completion and deletion. It also runs the existing S3 audio integration.

**Classification for the verified repository topology only:** `VULNERABILITY_PRESENT_BUT_CONTAINED`. The MinIO executable remains affected, and the scanner findings remain visible. The proof excludes an operator with Docker or in-container execution privileges, existing running containers, shared network namespaces, externally configured object-store endpoints and any production topology. Do not apply this claim to a container that bypasses its entrypoint or to an existing environment that has not been separately verified.

Other O1A findings remain open, including MinIO application and dependency advisories, CI service and builder OS packages, the end-of-life demo Redis base, the development `minimatch` advisory and incomplete browser or hosted runner provenance. No production artifact, risk acceptance, existing data volume, deployment or licensing decision is covered by this work.
